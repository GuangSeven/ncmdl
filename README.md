# ncmdl

网易云音乐终端版下载脚本。（原脚本：[![Greasy Fork](https://img.shields.io/badge/Greasy_Fork-网易云音乐歌曲下载-8a0000?logo=greasyfork&logoColor=white&style=flat)](https://greasyfork.org/scripts/459633)）

## 目标

这个仓库现在提供的是本地终端运行版，不再依赖篡改猴、页面注入和浏览器 DOM。核心思路是把原脚本里三类能力拆开：

1. 认证信息改为本地配置文件和环境变量，不再依赖浏览器里的 GM 存储。
2. 网络请求改为 Node.js 发起的 `fetch` 请求，继续使用网易云的加密请求方式。
3. 交互改为命令行参数和交互式提示，适合终端批量下载。

## 本地配置

脚本会把配置保存到 `~/.ncmdl/config.json`。

推荐准备这些信息：

- `cookie`：从已登录的浏览器中复制出来的网易云网页 Cookie，至少建议包含 `MUSIC_U` 和 `__csrf`。
- `userAgent`：桌面浏览器的 UA 字符串，默认已经内置了一个可用值。
- `downloadDir`：下载目录。
- `quality`：默认音质，例如 `jymaster`、`lossless`、`exhigh`、`standard`。
- `concurrency`：批量下载时的最大并发数，4-12，默认 4。可在交互式配置向导（选项 2）里调整，或用 `node src/cli.js config concurrency 8` 直接设置。

获取 Cookie 有两种方式：

1. **自动抓取（推荐）**：运行 `node src/cli.js cookie`，脚本会自动打开系统 Edge/Chrome 浏览器并跳转到网易云音乐，你登录后脚本自动提取 Cookie 并保存到本地配置。
2. **手动输入**：运行 `node src/cli.js setup`，按提示粘贴从浏览器开发者工具中复制的 Cookie。

## 使用

先安装 Node.js 18 或更高版本。

Windows 用户可以直接**双击项目根目录下的 `ncmdl.bat`** 打开交互式下载器（无需手动输入命令；窗口会在程序退出后停留以便查看结果）。也可以在仓库根目录用命令行执行：

```bash
node src/cli.js                     # 进入交互式菜单
node src/cli.js setup               # 手动输入配置
node src/cli.js cookie              # 自动打开浏览器抓取 Cookie（推荐）
node src/cli.js download 123456
node src/cli.js download https://music.163.com/song?id=123456
node src/cli.js config show
node src/cli.js config concurrency 8   # 设置最大并发下载数（4-12）
node src/cli.js tag "某歌.mp3" --song 123456   # 给本地文件补写网易云标签
```

### 批量下载（多首歌 / 整张专辑，多线程并发）

`download` 现在可以一次下载多首歌曲或整张专辑，并默认以 4 路并发同时下载：

```bash
# 多首歌曲：空格或逗号分隔
node src/cli.js download 123456 234567 345678
node src/cli.js download "123456,234567,345678"

# 整张专辑：传入专辑链接或 album: 前缀
node src/cli.js download https://music.163.com/#/album?id=123456
node src/cli.js download album:123456

# 调整并发数（允许 4-12，默认 4）
node src/cli.js download album:123456 --concurrency 8
```

- 支持的输入形态：纯数字歌曲 ID、歌曲/专辑链接、`album:123456` 专辑前缀；多首之间用空格、`,`、`，`、`;`、`、` 分隔。
- 裸数字按歌曲处理；专辑请用专辑链接或 `album:` 前缀，避免与歌曲 ID 混淆。
- 并发数可通过命令行 `--concurrency`、环境变量 `NCM_CONCURRENCY` 或配置文件里的 `concurrency` 字段设置，取值会自动收敛到 4-12。
- 每首歌独立下载与写入标签，单首失败不会中断整批；结束时打印成功/失败统计。同名文件会自动追加序号避免互相覆盖。
- 下载文件会按 `下载目录/专辑所属歌手/专辑名/文件名` 建立文件夹。**歌手文件夹名以该歌曲所在专辑的所属歌手为准**（合辑/精选集用专辑歌手而非单曲演唱者）；拿不到专辑信息时退回单曲歌手，再兜底“未知歌手”。
- 同时在 **歌手文件夹根目录保存高清歌手图片**（`artist.jpg` / `.png`）、在 **专辑文件夹根目录保存高清专辑封面**（`cover.jpg` / `.png`）：
  - 图片地址会自动去掉网易云的 `?param=300y300` 缩略图参数，改取原图（实测专辑封面 433–4000 像素、歌手头像 400–9837 像素；老专辑源图可能只有 433×433），并按真实图片格式落盘（接口地址常以 `.jpg` 结尾、内容其实是 PNG）。
  - 歌手图片取专辑所属歌手中的第一位（与歌手文件夹命名规则一致，多歌手合辑只保存首位歌手肖像）；专辑封面取专辑详情里的原图。
  - 冷门歌手没有官方肖像时网易云会返回默认占位图，脚本会按图片地址识别并跳过（不会把默认头像当成歌手图片）。
  - 图片属于附加产物：每类图片（歌手图片 / 专辑封面）失败最多提示一行，不影响歌曲下载；同一文件夹已有图片时跳过，重跑不会重复下载；整张专辑/多首歌曲共用文件夹时只下载一次。
- 下载后会写入音乐标签：标题、歌手、专辑、曲目/碟号、年份、专辑艺人、发行公司、**流派（取自网易云“曲风”，统一输出英文名且大项/小项作为独立标签，如 `Pop`、`Rock; Pop Rock`、`Jazz`）**、歌词（原文与翻译双语）、内嵌封面（多个歌手、多个曲风统一用 `; ` 分隔）以及**备注（= 专辑简介，专辑没有简介时不写）**；FLAC 写入 Vorbis Comment（`GENRE`/`LYRICS`/`COMMENT` + `DESCRIPTION` 双写备注，兼容只读 `DESCRIPTION` 的工具），MP3 写入 ID3v2.4（`TDRC`/`TCON`/`USLT`/`COMM`/`APIC`）。

### 本地文件补标签（`tag`）

从别处下载的歌、或网易云拿不到播放地址（提示“没有拿到可下载地址”）的歌，可以只取网易云的源信息，把标签写进已有文件：

```bash
node src/cli.js tag "D:\music\一人饮酒醉MC赵小六.mp3" --song 2737795869
# 可一次传多个文件，歌词/曲风/封面等元数据只请求一次
node src/cli.js tag a.mp3 b.flac --song 123456
```

- `--song` 必填，ID 取自歌曲页地址 `?id=` 后面的数字。
- 写入字段与 `download` 完全一致：标题、歌手、专辑、曲目、碟号、年份、专辑艺人、发行公司、流派、备注（= 专辑简介，有才写）、歌词（原文+翻译）、内嵌封面；`.mp3` 走 ID3v2.4（整标签替换，旧标签会被清除），`.flac` 走 Vorbis Comment + PICTURE。
- 文件不存在或类型不是 `.mp3`/`.flac` 会在联网前直接报错退出；单个文件写入失败不影响其余文件（退出码为 1）。

## 交互式菜单

直接运行 `node src/cli.js` 进入交互式菜单，无需记忆命令行参数：

```
ncmdl v1.0.0

1. 抓取 Cookie
2. 手动输入配置
3. 下载歌曲/专辑
4. 查看配置
5. 重置配置
0. 退出

请选择功能（←/→ 或 ↑/↓ 选择，回车确认，或直接输入数字）:
```

- 菜单支持两种操作方式：用 **←/→（或 ↑/↓）移动高亮（红字白底）后按回车**，或**直接输入数字即时进入对应选项**（无需再按回车）。
- 每次在菜单中执行操作前会自动清屏，让本次操作的输出从干净屏幕开始；**仅在真实终端生效**，管道/文件重定向时保持纯文本输出，不会注入清屏转义序列。
- 向导（选项 2）里的 **User-Agent、默认音质、文件名模式** 改成了可切换的选项（数字/方向键选择，回车确认；UA 支持预设与自定义输入）；向导末尾还会询问**最大并发下载数（4-12）**，直接回车沿用当前值。

菜单支持终端与脚本两种输入方式：

- 终端（TTY）下按提示操作即可。Cookie 输入支持直接粘贴：粘贴会启用终端的 bracketed paste 模式（主流终端均支持），整个粘贴内容（无论被终端拆成多少次读取、行间停顿多久）都会完整识别，粘贴结束即自动确认；粘贴自带的尾随换行会被自动吸收，无需刻意追加回车。多行粘贴会被整体拒绝并提示重新粘贴（向导会重新询问 Cookie，绝不把截断后的首行写入配置，也不会静默沿用旧值）。不支持 bracketed paste 的终端退化为"键入后按回车确认"：回车即确认；若粘贴被终端拆成多次到达（无论行间停顿多久），后续行只要形如 Cookie（`key=value`）就会在下一个提示消费时识别为多行粘贴并整体拒绝——菜单场景恢复粘贴前保存的 Cookie，向导场景重新询问 Cookie——绝不把截断后的首行写入配置，也不让残留行漏入菜单队列。
- 脚本/管道/文件重定向输入时逐行喂入选项即可，每个提示恰好消费一行，例如 `printf "2\nMUSIC_U=xxx\n\n\n\n\n0\n" | node src/cli.js` 或 `node src/cli.js < menu.txt`；此时下载不会再询问是否更换 Cookie，直接使用现有配置。

## 交互方式

终端版不会再弹出 SweetAlert 或依赖网页按钮。当前脚本采用这几种交互方式：

- 没有传歌曲参数时（`node src/cli.js download`），会直接在终端里提示你输入歌曲 ID 或链接。
- 没有配置 cookie 时，会在初始化或下载时提示你补录。
- `config show` 只会展示脱敏后的 Cookie，避免直接把敏感信息打印到屏幕上。

## 浏览器版到终端版的调整

原 userscript 里依赖的这些内容在终端版里不再存在：

- `GM_*` 系列 API
- 页面注入的按钮、表格和弹窗
- 对评论区、歌单页、云盘页的 DOM 监听和拦截

这些都替换成了命令行参数、配置文件和普通 HTTP 请求。这样更适合批量任务，也更容易在 Windows 终端里直接运行。

## 当前实现范围

目前先把最核心的本地下载链路做成终端版：配置管理、Cookie 处理、歌曲信息获取和文件下载。原脚本里那些强依赖网页界面的功能，后续可以再按同样思路继续拆成子命令。
